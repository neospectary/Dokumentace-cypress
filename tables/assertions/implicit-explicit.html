Implicitní vs. explicitní assertions

V Cypressu existují dva základní způsoby, jak ověřovat stav aplikace: implicitní a explicitní assertions. Pochopení rozdílu vám pomůže psát čitelnější a stabilnější testy.

Co znamená „assertion“

Assertion = tvrzení, očekávání. Říkáte testu: „očekávám, že tento prvek bude viditelný“, „očekávám, že hodnota proměnné bude rovna 5“ atd. Pokud tvrzení neplatí, test selže.

Implicitní assertions

Implicitní assertions jsou zabudované přímo v Cypress příkazech. Příkaz sám v sobě obsahuje očekávání a Cypress podle něj automaticky čeká a vyhodnocuje stav.

Jak to poznám

  • Používáte klasické Cypress příkazy jako cy.get(), cy.contains(), cy.url(), cy.location(), cy.intercept()…
  • Tyto příkazy automaticky čekají, dokud není splněna jejich vnitřní podmínka (element existuje, je viditelný, request proběhl atd.).

Příklady implicitních assertions

// cy.get() implicitně asertuje, že element existuje v DOM
cy.get('[data-cy=\"submit-button\"]')

// cy.contains() implicitně asertuje, že text existuje
cy.contains('Uložit změny')

// cy.url() implicitně asertuje, že existuje URL (čeká na načtení stránky)
cy.url()

// cy.intercept() + cy.wait() implicitně asertuje, že request proběhl
cy.intercept('GET', '/api/users').as('getUsers')
cy.wait('@getUsers')

Kdy je to užitečné

  • Když jen potřebujete „něco získat“ (element, URL, response) a spolehnout se, že Cypress za vás počká.
  • Když nechcete psát extra should(), ale využít chytré čekání Cypressu.

Explicitní assertions

Explicitní assertions jsou tvrzení, která napíšete sami pomocí .should() nebo .and(). Říkáte přesně, co má platit: be.visible, have.text, eq, include atd.

Jak to poznám

  • V řetězu vidíte .should(...) nebo .and(...).
  • Uvnitř používáte assertion chainery jako be.visible, be.enabled, have.text, eq, deep.eq…

Příklady explicitních assertions

// Element je viditelný a povolený
cy.get('[data-cy=\"submit-button\"]')
  .should('be.visible')
  .and('be.enabled')

// Text v elementu
cy.get('[data-cy=\"toast-message\"]').should('have.text', 'Uloženo úspěšně')

// Práce s URL
cy.location('pathname').should('eq', '/settings/user')

// Práce s daty z API
cy.wait('@getUsers')
  .its('response.statusCode')
  .should('eq', 200)

Jak spolu implicitní a explicitní assertions spolupracují

V praxi téměř vždy používáte kombinaci obou: 

cy.get('[data-cy=\"user-row\"]')      // implicitně: element musí existovat
  .should('have.length', 5)           // explicitně: musí jich být přesně 5
  .first()                            // implicitně: musí existovat první prvek
  .should('contain.text', 'Nový uživatel') // explicitně: text v prvním řádku
  • Implicitní assertions se starají o to, že pracujete s platnými daty / elementy.
  • Explicitní assertions přesně definují, co má být splněno.

Kdy použít který typ

Stačí implicitní assertions

  • Když jen „chcete něco najít“ a hned s tím dál pracovat (např. cy.get(), cy.contains(), cy.url()).
  • Když vás v tu chvíli nezajímá konkrétní hodnota, ale jen to, že je něco dostupné.

Potřebujete explicitní assertions

  • Když chcete : text, číslo, viditelnost, třídu, atribut, počet prvků…
  • Když píšete podmínky business logiky (např. „musí se zobrazit hláška“, „řádků musí být 10“).
  • Když testujete výsledek akce (submit formuláře, volání API, změna stavu UI).

Shrnutí v jedné větě

  • Implicitní assertions: Cypress za vás automaticky čeká a kontroluje základní věci (existence, načtení).
  • Explicitní assertions: Vy sami píšete konkrétní očekávání pomocí .should() / .and().
