Dynamické čekání pomocí interceptů

Cypress automaticky čeká na elementy, animace a HTTP requesty. Nejspolehlivějším způsobem synchronizace testu s backendem je cy.intercept() + cy.wait('@alias') — zejména v Angular aplikacích, kde komponenty tahají data z API při inicializaci.

Proč nepoužívat cy.wait(ms)

Pevné čekání je anti-pattern. Cypress to říká explicitně ve své dokumentaci Best Practices. Problém je, že číslo, které zvolíš, je vždy špatně — buď zbytečně zpomaluje testy, nebo selže na pomalejším CI.

❌ Anti-pattern

cy.visit('/segments')
cy.wait(3000)                         // čeká vždy 3 s, i když data přijdou za 200 ms
cy.get('.segment-table').should('be.visible')

✅ Správně — čekej na skutečný HTTP request

cy.intercept('GET', '/api/segments').as('getSegments')
cy.visit('/segments')
cy.wait('@getSegments')               // pokračuje přesně ve chvíli, kdy data dorazí
cy.get('.segment-table').should('be.visible')
cy.wait(3000) cy.wait('@alias')

Syntaxe intercept — string vs. objekt

cy.intercept() lze volat třemi způsoby. Objekt se hodí, když potřebuješ větší přesnost nebo čitelnější zápis.

String forma — rychlá a jednoduchá

cy.intercept('GET', '/api/users').as('getUsers')
cy.intercept('POST', '/api/users').as('createUser')

Objekt forma — přesnější matching

// Stejný výsledek jako výše, ale explicitnější
cy.intercept({ method: 'GET', url: '/api/users' }).as('getUsers')

// Wildcard v URL — zachytí libovolné ID nebo segment
cy.intercept({ method: 'GET', url: '**/contact/grid-fields/v2/contact-list/**' }).as('getContactList')

Wildcard pravidla

cy.intercept('GET', '/api/**')              // ** = libovolný počet segmentů
cy.intercept('GET', '/api/users/*/posts')   //  * = právě jeden segment
cy.intercept('GET', /\/api\/users\/\d+/)    // regex — pro složitější patterny

Základní vzor: intercept → akce → wait

Klíčové pravidlo: cy.intercept() musí být definováno před akcí, která request spustí. V Angular aplikaci spouští komponenta HTTP volání při ngOnInit — tedy hned při navigaci.

✅ Správné pořadí

// 1. Registrace interceptu PŘED navigací
cy.intercept({ method: 'GET', url: '**/contact/grid-fields/v2/contact-list/**' }).as('getContactList')

// 2. Akce, která spustí request (Angular komponenta ho volá v ngOnInit)
cy.gridCell(0, 'name').click()

// 3. Počkej na dokončení requestu
cy.wait('@getContactList')

// 4. Teprve teď asertuj — data jsou zaručeně načtena
cy.url().should('include', '/detail/')
cy.dataCy('edit-segment-button').should('be.visible')

❌ Špatné pořadí — intercept po akci

cy.visit('/users')
cy.intercept('GET', '/api/users').as('getUsers')   // příliš pozdě, request již odešel
cy.wait('@getUsers')                                // timeout!

Čekání na více requestů najednou

Pokud stránka při načtení volá více API endpointů paralelně, počkej na všechny najednou. 

cy.intercept('GET', '/api/user').as('getUser')
cy.intercept('GET', '/api/notifications').as('getNotifications')
cy.intercept('GET', '/api/settings').as('getSettings')

cy.visit('/home')
cy.wait(['@getUser', '@getNotifications', '@getSettings'])   // čeká na všechny tři

cy.get('[data-cy="home-content"]').should('be.visible')

Opakované čekání na stejný alias

Každé cy.wait('@alias') čeká na další výskyt requestu. Skvělé pro paginaci nebo akce, které stejný endpoint volají vícekrát. 

cy.intercept('GET', '/api/items*').as('getItems')

cy.visit('/items')
cy.wait('@getItems')                        // 1. request — strana 1

cy.get('[data-cy="next-page"]').click()
cy.wait('@getItems')                        // 2. request — strana 2 (automaticky další)

Asertace na request a response

cy.wait('@alias') vrací celý interception objekt — můžeš asertovat na status kód, tělo odpovědi nebo tělo requestu.

Status kód

cy.wait('@getUsers').its('response.statusCode').should('eq', 200)

Tělo odpovědi

cy.wait('@getUsers')
  .its('response.body')
  .should('have.length', 3)

Tělo requestu (POST)

cy.intercept('POST', '/api/orders').as('createOrder')
cy.get('[data-cy="submit-order"]').click()

cy.wait('@createOrder')
  .its('request.body')
  .should('deep.include', { productId: 42, quantity: 2 })

Vzor: beforeEach s interceptem

Nejčastější pattern v reálných projektech — intercept a návštěva stránky v beforeEach, jednotlivé testy se starají jen o aserce. 

describe('User list page', () => {
  beforeEach(() => {
    cy.intercept('GET', '/api/users', { fixture: 'users.json' }).as('getUsers')
    cy.visit('/users')
    cy.wait('@getUsers')
  })

  it('zobrazí tabulku uživatelů', () => {
    cy.get('table tbody tr').should('have.length', 3)
  })

  it('zobrazí jméno prvního uživatele', () => {
    cy.get('table tbody tr').first().contains('Alice')
  })
})

Časté chyby

❌ Intercept registrován příliš pozdě

cy.visit('/users')
cy.intercept('GET', '/api/users').as('getUsers')   // request již proběhl!
cy.wait('@getUsers')                                // timeout

❌ Příliš obecný matcher překrývá specifický

cy.intercept('*').as('catchAll')   // zachytí vše — i requesty, které nechceš čekat

// Vždy buď specifický — rozlišuj metodu i URL
cy.intercept('GET', '/api/users').as('getUsers')
cy.intercept('POST', '/api/users').as('createUser')

❌ Přístup k aliasu po wait()

cy.wait('@getUsers')
cy.get('@getUsers')   // vrátí null — wait() alias spotřeboval

// Správně — použij hodnotu přímo z wait()
cy.wait('@getUsers').then((interception) => {
  expect(interception.response.body).to.have.length(3)
})
