Robustnost testů — opakované spouštění a odhalování flaky testů

Robustní test musí projít nejen jednou, ale opakovaně za sebou — bez pádu, bez úniku paměti, bez závislosti na náhodném načasování. Technika, kdy záměrně spustíš celý describe blok 10–15× v cyklu, odhalí chyby, které při jednorázovém běhu nikdy neuvidíš. Do produkční sady testů to nepatří, ale jako vývojářský nástroj kvality je to neocenitelné.

Co je flaky test a proč vzniká

Flaky test je test, který někdy projde a jindy selže — přestože se kód ani aplikace nezměnily. Při jednorázovém spuštění vypadá jako spolehlivý. Teprve opakované spouštění odhalí latentní problém.

Metoda 1 — Cypress._.times() uvnitř spec souboru

Lodash utilita Cypress._.times(n, fn) vygeneruje n samostatných it bloků se stejným obsahem. Každý běží jako nezávislý test — Cypress reporter ukáže všechny najednou. Ideální pro lokální ověření stability.

Základní použití

// Spustí stejný test 15× za sebou
Cypress._.times(15, (index) => {
  it(`[${index + 1}/15] uživatel se přihlásí a odhlásí`, () => {
    cy.visit('/login')
    cy.getBySel('email-input').type('jan@test.cz')
    cy.getBySel('password-input').type('heslo123')
    cy.getBySel('submit-button').click()

    cy.url().should('include', '/dashboard')
    cy.getBySel('logout-button').click()
    cy.url().should('include', '/login')
  })
})

Stress-test celého describe bloku

// Zabalíš existující describe do Cypress._.times()
// — POUZE lokálně, před commitem do produkce odstraň!
Cypress._.times(15, (i) => {
  describe(`[Cyklus ${i + 1}/15] Správa uživatelů`, () => {
    beforeEach(() => {
      cy.intercept('GET', '/api/users').as('getUsers')
      cy.visit('/users')
      cy.wait('@getUsers')
    })

    it('zobrazí seznam uživatelů', () => {
      cy.getBySel('users-table').should('be.visible')
      cy.getBySel('users-table').find('tr').should('have.length.gt', 0)
    })

    it('otevře detail uživatele', () => {
      cy.getBySel('user-row').first().click()
      cy.url().should('include', '/users/')
      cy.getBySel('user-detail-name').should('be.visible')
    })

    afterEach(() => {
      // Vždy vyčisti stav po každém cyklu
      cy.clearCookies()
      cy.clearLocalStorage()
    })
  })
})

Přístup k číslu iterace uvnitř testu

Cypress._.times(10, (k) => {
  it(`iterace ${k + 1}`, () => {
    cy.log(`Spouštím iteraci číslo ${k + 1}`)
    // ... test logic
  })
})

Metoda 2 — for cyklus uvnitř it bloku

Místo generování více it bloků lze cyklus vložit přímo dovnitř jednoho testu. Cypress příkazy se zařadí do fronty a provedou se sekvenčně. Vhodné pro testování opakované interakce (paginace, opakované vyhledávání, CRUD operace).

for cyklus v testu

it('opakovaně přidá a odebere položku z košíku', () => {
  cy.visit('/shop')

  for (let i = 0; i < 10; i++) {
    cy.log(`--- Cyklus ${i + 1}/10 ---`)

    // Přidej do košíku
    cy.getBySel('add-to-cart-button').first().click()
    cy.getBySel('cart-count').should('contain', '1')

    // Odeber z košíku
    cy.getBySel('remove-from-cart').click()
    cy.getBySel('cart-count').should('contain', '0')
  }
})

forEach s polem hodnot

it('vyhledá různé výrazy a vždy zobrazí výsledky', () => {
  const searchTerms = ['Jan', 'Marie', 'novák', 'test@test.cz', '123']

  cy.visit('/users')

  searchTerms.forEach((term) => {
    cy.getBySel('search-input').clear().type(term)
    cy.getBySel('search-button').click()
    cy.getBySel('results-list').should('be.visible')
    cy.getBySel('search-input').clear()
  })
})

Cyklus pro test paginace

it('projde prvních 5 stránek bez chyby', () => {
  cy.intercept('GET', '/api/users*').as('getUsers')
  cy.visit('/users')
  cy.wait('@getUsers')

  for (let page = 1; page <= 5; page++) {
    cy.log(`Stránka ${page}`)
    cy.getBySel('users-table').should('be.visible')
    cy.getBySel('pagination-info').should('contain', page)

    if (page < 5) {
      cy.getBySel('next-page-button').click()
      cy.wait('@getUsers')
    }
  }
})

Metoda 3 — cypress-repeat (celý test run)

Nástroj cypress-repeat od Gleba Bahmutova spouští celý Cypress run n× za sebou z příkazové řádky. Nemusíš měnit žádný kód v testech — ideální pro CI ověření nebo jednorázové stress testy celé sady.

Instalace

npm install --save-dev cypress-repeat

Použití z příkazové řádky

# Spustí testy 10× — zastaví se při prvním selhání
npx cypress-repeat run -n 10 --spec "cypress/e2e/login.cy.ts"

# Spustí testy 15× — dokud všechny neprojdou
npx cypress-repeat run -n 15 --until-passes --spec "cypress/e2e/users.cy.ts"

# Opakuje pouze dříve selhané spec soubory
npx cypress-repeat run -n 10 --until-passes --rerun-failed-only

# Debug výstup
DEBUG=cypress-repeat npx cypress-repeat run -n 5

Přístup k číslu běhu uvnitř testu

it('test zná číslo svého běhu', () => {
  const totalRuns = Cypress.env('cypress_repeat_n')    // celkový počet
  const currentRun = Cypress.env('cypress_repeat_k')  // aktuální (1 až n)

  cy.log(`Běh ${currentRun} z ${totalRuns}`)
})

Konfigurace Cypress retries — reaktivní přístup

Retries jsou opak opakovaného spouštění — nejde o proaktivní ověření stability, ale o reaktivní záchrannou síť při náhodném selhání. Vhodné pro CI prostředí, kde infrastructure občas zlobí.

Globální konfigurace v cypress.config.ts

import { defineConfig } from 'cypress'

export default defineConfig({
  e2e: {
    retries: {
      runMode: 2,   // 2 pokusy navíc při cypress run (CI)
      openMode: 0,  // žádné opakování při cypress open (lokálně)
    },
  },
})

Retries pro konkrétní test nebo describe

// Jen pro jeden test
it('načte data ze slabé sítě', { retries: { runMode: 3, openMode: 1 } }, () => {
  cy.visit('/dashboard')
  cy.getBySel('data-table').should('be.visible')
})

// Pro celý describe blok
describe('Integrace s externím API', { retries: { runMode: 2, openMode: 0 } }, () => {
  it('vrátí správný status', () => { ... })
  it('zobrazí data', () => { ... })
})

Únava paměti při opakovaných bězích

Pokud testy padají až v pozdějších cyklech (např. cyklus 12 z 15 selže, ale 1–11 projde), jde nejspíš o únik paměti. Cypress si v paměti drží snapshoty pro debugování — při stovkách testů to může způsobit pád celého prohlížeče.

Symptomy úniku paměti

// Test prochází v cyklech 1-10, ale v cyklu 11+ padá s chybou:
// "Aw Snap! Out of Memory" nebo "Browser tab crashed"
// Nebo jednoduše zpomaluje — test, který trval 5 s, trvá 60 s

Řešení 1 — omez počet testů držených v paměti

// cypress.config.ts
export default defineConfig({
  e2e: {
    numTestsKeptInMemory: 0,  // nulová hodnota = žádné snapshoty v paměti
  },
})

Řešení 2 — zvýšení heap paměti pro prohlížeč

// cypress.config.ts
export default defineConfig({
  e2e: {
    setupNodeEvents(on, config) {
      on('before:browser:launch', (browser, launchOptions) => {
        if (browser.family === 'chromium') {
          launchOptions.args.push('--js-flags=--max-old-space-size=3500')
        }
        return launchOptions
      })
    },
  },
})

Řešení 3 — cleanup po každém testu

afterEach(() => {
  cy.clearCookies()
  cy.clearLocalStorage()

  // Odstraň event listenery zaregistrované v testu
  cy.window().then((win) => {
    win.removeEventListener('resize', win.__testResizeHandler)
  })
})

Jak správně napsat robustní test — checklist

Než spustíš cyklický stress test, zkontroluj tyto body. Pokud test cykly neprojde, hledej chybu v tomto seznamu.

✅ Checklist robustního testu

// 1. Izolovaný stav — test nesmí záviset na předchozím testu
beforeEach(() => {
  cy.clearCookies()
  cy.clearLocalStorage()
  // nebo API reset stavu:
  cy.request('POST', '/api/test/reset')
})

// 2. Dynamické čekání — žádné cy.wait(ms)
cy.intercept('GET', '/api/data').as('getData')
cy.visit('/page')
cy.wait('@getData')              // ✅ čeká na reálný request

// 3. Stabilní selektory
cy.getBySel('submit-button')    // ✅ data-cy atribut
// cy.get('.btn.primary')       // ❌ CSS třída se může změnit

// 4. Aserce před interakcí
cy.getBySel('submit-button').should('be.visible').click()   // ✅
// cy.getBySel('submit-button').click()                     // ❌ může kliknout na skrytý element

// 5. Cleanup po testu
afterEach(() => {
  cy.clearCookies()
  cy.clearLocalStorage()
})

Vzor kompletního stress testu

// stress-test.cy.ts — POUZE lokálně, necommitovat!
const CYCLES = 15

Cypress._.times(CYCLES, (i) => {
  describe(`[${i + 1}/${CYCLES}] Login flow — stress test`, () => {
    beforeEach(() => {
      cy.clearCookies()
      cy.clearLocalStorage()
      cy.intercept('POST', '/api/auth/login').as('loginRequest')
    })

    it('přihlásí uživatele a přesměruje na dashboard', () => {
      cy.visit('/login')
      cy.getBySel('email-input').type('jan@test.cz')
      cy.getBySel('password-input').type('heslo123')
      cy.getBySel('submit-button').click()

      cy.wait('@loginRequest').its('response.statusCode').should('eq', 200)
      cy.url().should('include', '/dashboard')
      cy.getBySel('welcome-message').should('be.visible')
    })

    afterEach(() => {
      cy.clearCookies()
      cy.clearLocalStorage()
    })
  })
})

Reálný příklad z praxe — případ cy.route vs cy.intercept

Gleb Bahmutov (hlavní přispěvatel Cypressu) popsal případ, kdy test procházel stovky spuštění, ale občas selhal. Teprve po spuštění 1 000 iterací v cyklu (100 testů × 10 opakování) se ukázalo, že deprecated cy.route() občas nestačilo zachytit rychlé HTTP requesty. Migrace na cy.intercept() problém zcela odstranila — všech 1 000 iterací prošlo.

Poučení

// ❌ Deprecated — může občas selhat na zachycení rychlých requestů
cy.server()
cy.route('GET', '/api/users').as('getUsers')

// ✅ Moderní — spolehlivé i při rychlých requestech
cy.intercept('GET', '/api/users').as('getUsers')
