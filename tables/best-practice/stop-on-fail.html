Stop on Fail — zastavení testů při selhání

Cypress nabízí několik způsobů, jak zastavit provádění testů ve chvíli, kdy jeden selže. Technika se hodí hlavně v CI/CD prostředích, kde chceš ušetřit čas a prostředky, nebo u testů, kde pozdější kroky nedávají smysl bez úspěchu kroků předchozích. Zároveň má svá úskalí — musíš vědět, kdy ji použít a kdy naopak nechat testy běžet dál.

Přehled dostupných řešení

Cypress nenabízí jednoduchý globální přepínač bail: true. Existují ale čtyři různé přístupy podle toho, na jaké úrovni chceš zastavení aplikovat.

Cypress.stop() — vestavěné zastavení

Cypress.stop() je nativní příkaz bez nutnosti instalace pluginu. Zastaví provádění zbývajících testů v aktuálním spec souboru. V cypress open nechá Test Runner otevřený pro ladění, v cypress run spec přeskočí.

Základní použití — zastavit po prvním selhání

// cypress/support/e2e.ts
afterEach(function () {
  if (this.currentTest.state === 'failed') {
    Cypress.stop()
  }
})

Zastavení při nesplněné podmínce prostředí

// Zastav celý spec, pokud není dostupný API token
beforeEach(() => {
  cy.task('getApiToken').then((token) => {
    if (!token) {
      cy.log('❌ API token není dostupný — spec se zastaví')
      Cypress.stop()
    }
  })
})

Zastavení při špatném prostředí

// Zastav, pokud testy běží na špatném prostředí
before(() => {
  const env = Cypress.env('TEST_ENV')
  if (env !== 'staging' && env !== 'production') {
    cy.log(`❌ Neplatné prostředí: ${env}`)
    Cypress.stop()
  }
})

Omezení Cypress.stop()

// ✅ Zastaví zbývající testy v aktuálním spec souboru
// ❌ Nezastaví ostatní spec soubory v runu
// ❌ Nezastaví parallelizované rony na jiných strojích

// Pokud potřebuješ zastavit celý run → použij cypress-fail-fast

cypress-fail-fast — flexibilní zastavení

Plugin cypress-fail-fast od Javiera Brey je nejpopulárnější komunitní řešení. Umožňuje konfigurovat zastavení na úrovni celého runu, konkrétního describe bloku nebo jednotlivého it testu. Podporuje také nastavení počtu selhání před zastavením.

Instalace

npm install --save-dev cypress-fail-fast

Konfigurace pluginu (cypress.config.ts)

import { defineConfig } from 'cypress'
import cypressFailFast from 'cypress-fail-fast/plugin'

export default defineConfig({
  e2e: {
    setupNodeEvents(on, config) {
      cypressFailFast(on, config)
      return config
    },
  },
})

Import do support souboru (cypress/support/e2e.ts)

import 'cypress-fail-fast'

Globální zapnutí — zastaví celý run při prvním selhání

# Spuštění z příkazové řádky s env proměnnou
CYPRESS_FAIL_FAST_ENABLED=true npx cypress run

# Nebo v cypress.config.ts
export default defineConfig({
  env: {
    FAIL_FAST_ENABLED: true,
    FAIL_FAST_STRATEGY: 'run',   // 'spec' nebo 'run'
  },
})

Zapnutí jen pro kritické describe bloky

// Fail-fast ZAPNUTO — kritická autentizační suite
describe('Přihlašovací flow', { failFast: { enabled: true } }, () => {
  it('zobrazí přihlašovací formulář', () => {
    cy.visit('/login')
    cy.getBySel('login-form').should('be.visible')
  })

  it('přihlásí uživatele se správnými údaji', () => {
    cy.getBySel('email-input').type('jan@test.cz')
    cy.getBySel('password-input').type('heslo123')
    cy.getBySel('submit-button').click()
    cy.url().should('include', '/dashboard')
  })

  it('zobrazí uvítací zprávu', () => {
    // Tento test se přeskočí, pokud předchozí selže
    cy.getBySel('welcome-message').should('be.visible')
  })
})

// Fail-fast VYPNUTO — nezávislé smoke testy
describe('Smoke testy stránek', { failFast: { enabled: false } }, () => {
  it('homepage je dostupná', () => { cy.visit('/') })
  it('produkty jsou dostupné', () => { cy.visit('/products') })
  it('kontakt je dostupný', () => { cy.visit('/contact') })
})

Zastavení až po N selháních

export default defineConfig({
  env: {
    FAIL_FAST_ENABLED: true,
    FAIL_FAST_BAIL: 3,           // zastav až po 3 selháních, ne po prvním
    FAIL_FAST_STRATEGY: 'run',
  },
})

cypress-skip-this-test — přeskočení závislých testů

Plugin od Gleba Bahmutova řeší specifický případ: záměrně závislé testy, kde každý krok navazuje na předchozí. Místo úplného zastavení runu přeskočí zbývající testy v describe bloku — v reportu se zobrazí jako skipped, ne jako failed.

Instalace

npm install --save-dev cypress-skip-this-test

Použití pro step-by-step flow

import { skipIfPreviousTestsFailed } from 'cypress-skip-this-test'

// testIsolation: false — sdílíme stav mezi testy (nutné pro step flow)
describe('Checkout flow', { testIsolation: false }, () => {
  beforeEach(skipIfPreviousTestsFailed)

  it('krok 1 — přidá produkt do košíku', () => {
    cy.visit('/shop')
    cy.getBySel('product-card').first().click()
    cy.getBySel('add-to-cart').click()
    cy.getBySel('cart-count').should('contain', '1')
  })

  it('krok 2 — přejde do košíku', () => {
    // Přeskočí se, pokud krok 1 selhal
    cy.getBySel('cart-icon').click()
    cy.url().should('include', '/cart')
  })

  it('krok 3 — vyplní doručovací adresu', () => {
    // Přeskočí se, pokud krok 2 selhal
    cy.getBySel('shipping-address').type('Václavské náměstí 1, Praha')
    cy.getBySel('next-step-button').click()
  })

  it('krok 4 — dokončí objednávku', () => {
    // Přeskočí se, pokud krok 3 selhal
    cy.getBySel('confirm-order-button').click()
    cy.getBySel('order-success-message').should('be.visible')
  })
})

Kdy stop-on-fail použít a kdy ne

✅ Použij stop-on-fail, když…

// 1. Testy jsou záměrně závislé — pozdější kroky nedávají smysl bez předchozích
//    Příklad: login → přidání do košíku → platba

// 2. Selže kritická podmínka prostředí
//    Příklad: API server nedostupný, chybí autentizační token

// 3. Chceš šetřit čas a prostředky v CI/CD
//    Příklad: velká sada testů na placené CI infrastruktuře

// 4. Chceš rychlou zpětnou vazbu
//    Příklad: developer chce vědět, jestli jeho PR prošlo, co nejdřív

❌ Nepoužívej stop-on-fail, když…

// 1. Testy jsou nezávislé a chceš vidět všechna selhání najednou
//    Příklad: smoke testy pro 20 různých stránek

// 2. Ladíš flaky testy
//    Zastavení při prvním selhání ti ukryje ostatní problémy

// 3. Máš nestabilní test suite
//    Jeden flaky test zastaví všechno ostatní

// 4. Potřebuješ kompletní report o zdraví aplikace
//    Příklad: release QA — chceš seznam VŠECH chyb, ne jen první

Proč Cypress nemá nativní --bail přepínač

PR číslo 7892 navrhoval přidat --bail flag přímo do Cypress CLI. Byl ale uzavřen bez sloučení. Cypress tým se místo toho rozhodl pro sofistikovanější řešení přes Cypress Cloud — Auto Cancellation.

Proč Cloud Auto Cancellation místo --bail?

// Jednoduchý --bail flag má problém v paralelním prostředí:
// Stroj A selže → zastaví svůj run
// Stroj B, C, D stále běží → plýtvají prostředky

// Cypress Cloud Auto Cancellation řeší koordinaci přes všechny stroje:
// Stroj A selže → Cloud pošle signál strojům B, C, D → všichni se zastaví

// Spuštění s Auto Cancellation:
npx cypress run \
  --record \
  --parallel \
  --ci-build-id $CI_BUILD_ID \
  --auto-cancel-after-failures 1

// Vypnutí pro konkrétní run:
npx cypress run --record --auto-cancel-after-failures false

Auto Cancellation je dostupné v Business a Enterprise plánech Cypress Cloud od verze 6.8.0.

Kompletní příklad — kombinace přístupů

Reálný projekt obvykle kombinuje více technik: globální zastavení pro kritické chyby prostředí, cypress-fail-fast pro důležité flow sady a běžné nezávislé testy bez omezení.

cypress/support/e2e.ts — globální guard

import 'cypress-fail-fast'

// Zastav celý spec, pokud selže předpoklad prostředí
before(() => {
  cy.request({ url: '/health', failOnStatusCode: false }).then((response) => {
    if (response.status !== 200) {
      cy.log('❌ Aplikace není dostupná — zastavuji spec')
      Cypress.stop()
    }
  })
})

cypress.config.ts

import { defineConfig } from 'cypress'
import cypressFailFast from 'cypress-fail-fast/plugin'

export default defineConfig({
  e2e: {
    setupNodeEvents(on, config) {
      cypressFailFast(on, config)
      return config
    },
    // Fail-fast je vypnutý globálně — zapíná se selektivně v describe
    env: {
      FAIL_FAST_ENABLED: false,
    },
    // Šetři paměť při dlouhých runech
    numTestsKeptInMemory: 0,
  },
})

cypress/e2e/auth.cy.ts — fail-fast pro kritický flow

import { skipIfPreviousTestsFailed } from 'cypress-skip-this-test'

// Fail-fast: selhání přihlášení zastaví celý describe
describe('Autentizační flow', { failFast: { enabled: true } }, () => {
  beforeEach(() => {
    cy.clearCookies()
    cy.clearLocalStorage()
  })

  it('zobrazí přihlašovací stránku', () => {
    cy.visit('/login')
    cy.getBySel('login-form').should('be.visible')
  })

  it('přihlásí uživatele', () => {
    cy.visit('/login')
    cy.getBySel('email-input').type('jan@test.cz')
    cy.getBySel('password-input').type('heslo123')
    cy.getBySel('submit-button').click()
    cy.url().should('include', '/dashboard')
  })

  it('zobrazí profil přihlášeného uživatele', () => {
    cy.getBySel('user-avatar').should('be.visible')
    cy.getBySel('user-name').should('contain', 'Jan')
  })
})

// Nezávislé testy — fail-fast vypnutý, chceme vidět všechna selhání
describe('Smoke testy veřejných stránek', { failFast: { enabled: false } }, () => {
  const pages = ['/', '/about', '/contact', '/pricing', '/blog']

  pages.forEach((path) => {
    it(`stránka ${path} je dostupná`, () => {
      cy.visit(path)
      cy.getBySel('main-content').should('be.visible')
    })
  })
})

Doporučení Cypress komunity

Gleb Bahmutov (bývalý VP Engineering v Cypress) opakovaně zdůrazňuje základní filosofii: testy by měly být nezávislé. Stop-on-fail je pragmatický kompromis, ne ideální stav.

Kdy je závislost testů přijatelná

// Záměrný step-by-step flow je OK, pokud:
// 1. Je jasně dokumentovaný
// 2. Každý krok má smysl jako samostatný test
// 3. Celý flow testuje jednu ucelenou user journey

// Použij cypress-data-session pro sdílení stavu bez závislostí
// (lepší než testIsolation: false)
cy.dataSession('loggedInUser', () => {
  cy.loginAsAdmin()
  return cy.getCookie('session')
}, {
  validate: (session) => session !== null,
})
