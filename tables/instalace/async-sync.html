Synchronní vs. asynchronní operace

Než začneš psát testy v Cypressu, musíš pochopit jeden klíčový koncept — jak JavaScript (a tedy i Cypress) pracuje s časem a čekáním. Bez tohoto pochopení bude spousta věcí v Cypressu vypadat jako magie. S ním dává všechno smysl.

Synchronní operace — krok za krokem

Synchronní znamená, že se věci dějí jedna po druhé, v pořadí. Každý krok musí dokončit, než začne další.

Představ si recept na snídani

1. Dej vodu do konvice
2. Počkej, dokud se voda neuvaří          ← stojíš a čekáš, nic jiného neděláš
3. Nalej vodu do hrnku
4. Přidej čaj
5. Počkej 3 minuty                        ← zase čekáš, nepohneš se
6. Vyber čajový sáček
7. Snídeň je hotová

V synchronním světě stojíš u konvice a civíš na ni. Neděláš nic jiného. Teprve až voda dovaří, jdeš dál.

Takto funguje většina běžného kódu — řádek 1, pak řádek 2, pak řádek 3. Počítač čeká na výsledek každého kroku, než přejde na další.

Asynchronní operace — spusť a jdi dál

Asynchronní znamená, že spustíš operaci, ale nečekáš na její dokončení — jdeš dělat něco jiného. Až operace skončí, dostaneš signál a vrátíš se k výsledku.

Stejný recept, ale chytřeji

1. Dej vodu do konvice a zmáčkni tlačítko
2. → Konvice vaří sama, ty mezitím:
   - nakrájíš chleba
   - vytáhneš máslo z lednice
   - namažeš chleba
3. Konvice zapípá → vrátíš se, naleješ vodu
4. Snídeň je hotová — a mnohem rychleji!

Asynchronní operace jsou typicky věci, které něco trvají — načítání dat ze serveru, čtení souboru, čekání na odpověď API. Místo aby počítač stál a čekal, spustí operaci a zatím dělá něco jiného.

Proč na tom záleží v JavaScriptu?

JavaScript běží v prohlížeči a má jedno zásadní omezení: je jednovláknový. To znamená, že může v jeden moment dělat jen jednu věc. Pokud by synchronně čekal na odpověď serveru (třeba 2 sekundy), celý prohlížeč by se na tu dobu zasekl — nešlo by klikat, scrollovat, nic.

Proto JavaScript používá asynchronní přístup skoro všude, kde jde o čekání. Typické asynchronní operace:

  • Načítání dat z API (fetch, XMLHttpRequest)
  • Čtení a zápis souborů
  • Čekání na vstup od uživatele
  • Načítání obrázků a skriptů
  • Jakékoliv čekání na časovač (setTimeout)

Jak JavaScript řeší asynchronitu — Promise a callback

V JavaScriptu existují dva hlavní způsoby, jak pracovat s asynchronními operacemi:

Callback — "zavolej mě až budeš hotový"

Předáš funkci, která se zavolá ve chvíli, kdy operace skončí. Jako bys příteli řekl: „Až uvaříš kávu, zavolej mi." 

setTimeout(() => {
  console.log('Toto se zobrazí za 2 sekundy')
}, 2000)

console.log('Toto se zobrazí hned')

// Výstup:
// "Toto se zobrazí hned"
// (po 2 sekundách)
// "Toto se zobrazí za 2 sekundy"

Promise — "slib, že ti dám výsledek"

Promise je objekt, který reprezentuje hodnotu, která teď ještě neexistuje, ale existovat bude. Jako restaurace, která ti dá číslíček — „slibuji, že ti jídlo přinesu". 

fetch('https://api.example.com/users')     // spustí request, hned vrátí Promise
  .then(response => response.json())       // až přijde odpověď, zpracuj ji
  .then(data => console.log(data))         // až je zpracovaná, zobraz data
  .catch(error => console.log('Chyba!'))   // nebo zachyť chybu

async/await — modernější zápis Promise

async/await dělá totéž co Promise, ale kód vypadá synchronně — přehledněji. Pod kapotou je to pořád asynchronní operace. 

async function nactiUzivatele() {
  const response = await fetch('https://api.example.com/users')  // počkej na odpověď
  const data = await response.json()                             // počkej na zpracování
  console.log(data)
}

Jak to řeší Cypress — command queue

A teď k tomu nejdůležitějšímu. Cypress funguje jinak než běžný JavaScript. Když napíšeš cypress test, příkazy se nevykonají hned — Cypress si je zapíše do fronty (command queue) a pak je spouští jeden po druhém, každý až po dokončení předchozího.

Co se stane, když napíšeš tento test

cy.visit('/login')                         // 1. přidá do fronty
cy.get('[data-cy="email"]').type('a@b.c')  // 2. přidá do fronty
cy.get('[data-cy="submit"]').click()       // 3. přidá do fronty
cy.url().should('include', '/dashboard')   // 4. přidá do fronty

Cypress nejprve projde celý test a sestaví frontu příkazů. Teprve pak začne frontu vykonávat — a každý příkaz čeká na dokončení předchozího. Ty nemusíš psát žádné await, žádné callbacky — Cypress to řídí za tebe.

Vizuálně — fronta příkazů

Fronta:  [visit] → [get+type] → [get+click] → [url+should]
                     ↓ až skončí visit
                               ↓ až skončí type
                                             ↓ až skončí click
                                                            ↓ vykoná should

Nejčastější záludnost — proměnné se neplní hned

Toto mate úplně každého začátečníka. Protože Cypress příkazy jsou asynchronní (vykonají se až „někdy"), nelze jejich výsledek uložit do běžné proměnné a hned ho použít.

❌ Toto nefunguje — klasická chyba

// Vypadá logicky, ale je špatně!
const text = cy.get('.title').invoke('text')   // text je teď undefined!
console.log(text)                              // vypíše undefined, ne skutečný text

✅ Správně — pracuj s hodnotou uvnitř .then()

cy.get('.title').invoke('text').then((text) => {
  console.log(text)    // tady text skutečně existuje
  cy.log(text)
})

✅ Nebo použij alias

cy.get('.title').invoke('text').as('nadpis')

cy.get('@nadpis').then((text) => {
  cy.log(text)
})

Proč v Cypressu nepoužíváš async/await

Možná tě napadne: „Když je Cypress asynchronní, proč nepíšu await cy.get()?" Odpověď: protože Cypress není Promise. Cypress příkazy vrací speciální objekt (Chainable), ne Promise. Kdybys použil await, rozbil bys command queue a testy by přestaly fungovat správně. 

// ❌ NIKDY toto v Cypressu nedělej
it('špatný test', async () => {
  await cy.visit('/login')                        // rozbije command queue!
  const email = await cy.get('[data-cy="email"]') // nefunguje správně
})

// ✅ Správně — bez async/await, Cypress řídí pořadí sám
it('správný test', () => {
  cy.visit('/login')
  cy.get('[data-cy="email"]').type('test@test.cz')
})
