Co je test a jak funguje testování

Než začneš psát Cypress testy, musíš rozumět tomu, proč testy existují, co přesně dělají a jak se test liší od assertion. Bez tohoto základu budeš kopírovat příkazy bez pochopení.

Co je test

Test je automatická kontrola, která ověřuje, že aplikace funguje tak, jak má. Místo aby člověk ručně klikal po webu a koukal, jestli vše funguje, napíše kód, který to udělá za něj — rychleji, přesněji a opakovaně.

Analogie — výrobní linka s kontrolou kvality

Představ si továrnu na žárovky. Na konci výrobní linky je stroj, který každou žárovku otestuje — zapne ji, změří jas, zkontroluje napětí. Pokud žárovka nevyhoví, stroj ji vyřadí. Bez tohoto stroje by museli zaměstnanci kontrolovat každou žárovku ručně.

Cypress je takový stroj pro tvoji webovou aplikaci. Pokaždé, kdy se změna kódu „vyrobí", Cypress projde aplikaci a zkontroluje, že všechno stále funguje.

Kdy test projde a kdy selže

Test projde (pass) ✅

Test projde, pokud všechna ověření (assertions) v testu jsou pravdivá — aplikace se chová přesně tak, jak test očekává. 

it('přihlášení funguje', () => {
  cy.visit('/login')
  cy.get('[data-cy="email"]').type('test@test.cz')
  cy.get('[data-cy="password"]').type('heslo123')
  cy.get('[data-cy="submit"]').click()
  cy.url().should('include', '/dashboard')    // ← assertion: URL obsahuje /dashboard
  // Pokud URL skutečně obsahuje /dashboard → test PROJDE ✅
})

Test selže (fail) ❌

Test selže, pokud jakékoliv ověření není splněno — aplikace se chová jinak, než test očekává. 

it('přihlášení funguje', () => {
  cy.visit('/login')
  cy.get('[data-cy="email"]').type('test@test.cz')
  cy.get('[data-cy="password"]').type('spatne-heslo')
  cy.get('[data-cy="submit"]').click()
  cy.url().should('include', '/dashboard')    // ← assertion selže!
  // URL je stále /login, ne /dashboard → test SELŽE ❌
})

Co je assertion (ověření, tvrzení)

Assertion je konkrétní tvrzení o tom, jaký stav má mít aplikace. Je to srdce každého testu. Bez assertion test nic neověřuje — jen projde stránku a nic nekontroluje.

Assertion v Cypressu — .should()

cy.get('[data-cy="title"]').should('be.visible')
//                           ↑ assertion: element musí být viditelný

cy.get('[data-cy="error"]').should('have.text', 'Nesprávné heslo')
//                           ↑ assertion: element musí mít tento text

cy.url().should('include', '/dashboard')
//        ↑ assertion: URL musí obsahovat /dashboard

cy.get('[data-cy="items"]').should('have.length', 5)
//                           ↑ assertion: musí existovat právě 5 elementů

Test bez assertion — k ničemu

// ❌ Tento test vždy projde — nic neověřuje!
it('navštívím login stránku', () => {
  cy.visit('/login')
  cy.get('[data-cy="email"]').type('test@test.cz')
  // žádná assertion → test nikdy nespadne → nemá smysl
})

// ✅ Správně — s assertion
it('login stránka zobrazí formulář', () => {
  cy.visit('/login')
  cy.get('[data-cy="login-form"]').should('be.visible')    // assertion!
  cy.get('[data-cy="submit"]').should('be.enabled')        // assertion!
})

Struktura testu — describe a it

Cypress používá strukturu z testovacího frameworku Mocha: describe() je skupina testů (test suite), it() je jeden konkrétní test (test case). 

describe('Login stránka', () => {               // skupina testů
  it('zobrazí přihlašovací formulář', () => {   // jeden test
    cy.visit('/login')
    cy.get('[data-cy="login-form"]').should('be.visible')
  })

  it('přihlásí uživatele se správnými údaji', () => {  // druhý test
    cy.visit('/login')
    cy.get('[data-cy="email"]').type('test@test.cz')
    cy.get('[data-cy="password"]').type('heslo123')
    cy.get('[data-cy="submit"]').click()
    cy.url().should('include', '/dashboard')
  })

  it('zobrazí chybu při špatném hesle', () => {    // třetí test
    cy.visit('/login')
    cy.get('[data-cy="email"]').type('test@test.cz')
    cy.get('[data-cy="password"]').type('spatne')
    cy.get('[data-cy="submit"]').click()
    cy.get('[data-cy="error-message"]').should('be.visible')
  })
})

Proč takhle strukturovat?

  • describe() — sdružuje testy, které testují stejnou část aplikace. Jméno popisuje, co testujeme (stránku, komponentu, funkci).
  • it() — jeden konkrétní scénář. Jméno popisuje, co má aplikace dělat. Čti ho jako větu: „Mělo by... (it should...)"

Jak pojmenovat test

Název testu musí být tak jasný, že při selhání okamžitě víš, co se rozbilo — bez čtení kódu.

Druhy testů — co je e2e

Existují různé druhy testů — Cypress se zaměřuje hlavně na e2e (end-to-end) testy.

Druh testuCo testujePříklad
Unit test Jednu izolovanou funkci nebo třídu Funkce secti(2, 3) vrátí 5
Integration test Spolupráci více částí systému Service správně zavolá API a zpracuje odpověď
E2E test Celý průchod aplikací jako uživatel Uživatel se přihlásí, najde produkt, přidá do košíku, zaplatí

E2e test simuluje skutečného uživatele — otevře prohlížeč, kliká, vyplňuje formuláře, čeká na odpovědi serveru. Cypress je navržený přesně pro tento typ testů.

Proč vůbec psát testy?

  • Zachytí chyby dříve — test selže při každém buildu, ne až u zákazníka
  • Nebojíš se změn — po refaktoringu víš, že nic nerozbíjíš
  • Dokumentace chování — testy popisují, jak má aplikace fungovat
  • Rychlejší vývoj — nemusíš ručně proklikat celou aplikaci po každé změně
  • Klid před releasem — zelené testy = sebejistota při nasazení
