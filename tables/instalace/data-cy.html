Atribut data-cy

V každém příkladu v Cypressu narazíš na [data-cy="..."]. Není to náhoda ani magie — je to záměrné rozhodnutí, jak psát testy, které nepřestanou fungovat při každé změně designu nebo HTML struktury.

Co jsou data atributy

HTML umožňuje přidat k libovolnému elementu vlastní atributy s prefixem data-. Prohlížeč je ignoruje (nepřidávají styl, nemají speciální funkci), ale jsou dostupné v JavaScriptu a CSS. 

<!-- Vlastní data atributy -- prohlížeč je ignoruje, ty je čteš -->
<button data-cy="submit-btn" data-testid="confirm" data-role="primary">
  Odeslat
</button>

data-cy je konvence Cypress komunity. Mohl by se jmenovat data-test, data-testid nebo cokoliv jiného — důležité je, že slouží výhradně pro testy.

Proč ne class nebo ID?

Problém s třídami (class)

<!-- Dnes -->
<button class="btn btn-primary submit-button">Odeslat</button>

<!-- Po redesignu -->
<button class="MuiButton-root MuiButton-contained">Odeslat</button>

Třídy patří CSS stylistovi. Změní je při redesignu nebo přechodu na jinou knihovnu (Material UI, Bootstrap). Tvůj test okamžitě spadne — přitom aplikace funguje správně. Test selhal jen proto, že se změnil styl, ne funkce.

Problém s ID

<!-- ID musí být unikátní na celé stránce -->
<!-- V dynamických aplikacích (React, Angular) se ID generují automaticky -->
<input id="mat-input-0" />    <!-- Angular Material -- číslo se mění! -->
<input id="mat-input-1" />
<input id="mat-input-2" />

Automaticky generovaná ID jsou nestabilní — změní se při přidání nového pole na stránku. Test pak hledá #mat-input-3 místo #mat-input-2 a selže.

Problém s textem elementu

cy.contains('Odeslat').click()   // funguje jen v češtině!
cy.contains('Submit').click()    // anglická lokalizace → test padá

Pokud aplikace podporuje více jazyků nebo se změní překlad tlačítka, test přestane fungovat.

Řešení — data-cy atribut

data-cy atribut patří výhradně testům. Vývojář ho nepřejmenuje, designer ho nevidí, překlad ho neovlivní. Je to smlouva: „tento atribut tu je jen pro Cypress."

Přidání do HTML (nebo Angular šablony)

<!-- Statický HTML -->
<button data-cy="submit-btn">Odeslat</button>
<input data-cy="email-input" type="email" />
<div data-cy="error-message">Nesprávné heslo</div>

<!-- Angular šablona -->
<button data-cy="login-btn" (click)="login()">Přihlásit</button>
<mat-error data-cy="email-error">{{ emailError }}</mat-error>

Použití v Cypress testu

cy.get('[data-cy="submit-btn"]').click()
cy.get('[data-cy="email-input"]').type('test@test.cz')
cy.get('[data-cy="error-message"]').should('be.visible')

Zkrácení pomocí vlastního příkazu (volitelné)

// cypress/support/commands.ts
Cypress.Commands.add('dataCy', (selector) => {
  return cy.get(`[data-cy="${selector}"]`)
})

// Použití — kratší zápis
cy.dataCy('submit-btn').click()
cy.dataCy('email-input').type('test@test.cz')

Konvence pojmenování

Název by měl popisovat co element dělá nebo co je, ne jak vypadá. Používej kebab-case (malá písmena, pomlčky).

❌ Špatně✅ SprávněProč
data-cy="btn1"data-cy="submit-btn"Popisuje funkci, ne pořadí
data-cy="redButton"data-cy="delete-btn"Popisuje akci, ne barvu
data-cy="input"data-cy="email-input"Specifikuje, co input je
data-cy="div3"data-cy="user-card"Popisuje obsah, ne strukturu
data-cy="Odeslat"data-cy="contact-form-submit"Jazyk-neutrální, specifikuje kontext

Odstraňování data-cy z produkčního buildu

Pokud nechceš, aby se data-cy atributy dostaly do produkce (zbytečně zvětšují HTML), lze je automaticky odstranit při buildu. Pro Angular existuje plugin babel-plugin-jsx-remove-data-test-id, nebo lze napsat vlastní webpack/esbuild transformaci. 

// Alternativně — podmíněné přidání v Angular
// Atribut se přidá jen v non-production buildech
<button [attr.data-cy]="!isProd ? 'submit-btn' : null">Odeslat</button>

Pro většinu projektů to ale není nutné — data-cy atributy jsou malé, neovlivňují výkon ani SEO.
