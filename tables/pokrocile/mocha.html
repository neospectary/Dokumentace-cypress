Mocha BDD syntaxe v Cypressu

Cypress používá jako testovací „motor“ knihovnu Mocha v BDD syntaxi. Všechny tvoje testy jsou postavené na těchto funkcích: describe(), context(), it(), before(), beforeEach(), afterEach(), after(), .only() a .skip().

Oficiální dokumentace: Bundled Libraries – Mocha →

Základní BDD struktura

describe() – skupina testů

describe() popisuje skupinu testů (funkcionalitu, stránku, modul). Uvnitř jsou konkrétní testy pomocí it(). 

describe('Mailing list', () => {
  it('vytvoří nový mailing list', () => {
    // test krok
  });
});

context() – alias pro describe()

context() je jen alias pro describe(). Používá se, když chceš zdůraznit „kontext“ (např. „když je uživatel přihlášený“). 

context('když je uživatel přihlášený', () => {
  it('vidí dashboard', () => {
    // test krok
  });
});

it() – samotný test

it() definuje jednotlivý test – jeden konkrétní scénář nebo chování, které ověřuješ. 

it('zobrazí notifikaci po uložení', () => {
  // Arrange + Act
  cy.dataCy('save-button').click();

  // Assert
  cy.dataCy('notification')
    .should('be.visible')
    .and('contain.text', 'Uloženo');
});

before(), beforeEach(), afterEach(), after()

Mocha poskytuje „hooky“ pro nastavení a úklid před/po testech. Cypress je používá stejně, jen s automatickou podporou asynchronních příkazů.

before() – jednou před všemi testy

before(() => {
  // Např. přihlášení jen jednou
  cy.tokenAuth('/dashboard');
});

beforeEach() – před každým testem

beforeEach(() => {
  // Např. otevření výchozí stránky před každým testem
  cy.visit('/mailing-list');
});

afterEach() – po každém testu

afterEach(() => {
  // Např. úklid dat, reset stavu, logování
});

after() – jednou po všech testech

after(() => {
  // Např. odhlášení, úklid testovacích dat
});

.only() a .skip() – filtrování testů

.only() – spustit jen vybrané testy

Pro ladění můžeš použít .only – Cypress/Mocha spustí jen označené testy/skupiny. 

describe.only('Mailing list', () => {
  it('vytvoří nový mailing list', () => { ... });
  it('smaže mailing list', () => { ... });
});

it.only('ladím jen tento test', () => { ... });

.skip() – dočasně přeskočit test

it.skip('dočasně nefunkční scénář', () => {
  // tento test se neprovede
});

Pozor: nenechávej .only() v kódu při commitu do repozitáře – v CI by se spustila jen malá část testů.

Asynchronní podpora a Cypress

Mocha umí pracovat s asynchronním kódem (callback done, Promise). Cypress ale řídí asynchronitu sám pomocí command queue, takže v it() a hookách prostě píšeš Cypress příkazy (cy.get(), cy.request() atd.) bez použití async/await nebo done.

Doporučený styl v Cypressu

it('pracuje s asynchronní odpovědí', () => {
  cy.request('/api/user')
    .its('body')
    .its('name')
    .should('eq', 'John');
});

Mocha se postará o strukturu testu a lifecycle (before/after), Cypress o správné načasování a retry příkazů.

Jak kombinovat Mocha, Chai a Cypress

  • Mocha – struktura testů: describe(), it(), hooky.
  • Chai – assertions (např. expect(), should()), v Cypressu hlavně přes .should().
  • Chai-jQuery – DOM assertions jako be.visible, have.text, have.class.
describe('Dashboard', () => {
  beforeEach(() => {
    cy.tokenAuth('/dashboard');
  });

  it('zobrazí souhrnné statistiky', () => {
    cy.dataCy('stats-card')
      .should('be.visible')
      .and('have.length.at.least', 1);
  });
});

Shrnutí

  • Mocha dává Cypressu strukturu testů (BDD: describe/it, hooky).
  • Většinu času budeš psát kombinaci Mocha struktur + Cypress příkazů + Chai assertions.
  • Pro ladění používej .only() a .skip(), ale nenechávej je v produkčním kódu.
